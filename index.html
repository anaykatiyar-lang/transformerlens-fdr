01 / The problem

Every extra component
is another hypothesis.

Activation patching is a powerful way to ask which internal components contribute to a model behavior. But a sweep across many heads or layers can surface small effects by chance.

TransformerLens-FDR keeps the effect measurement visible while making the inferential step explicit: what would your data look like if the effect were absent?

02 / Choose your evidence

Three paths. One rule:
the null comes first.

Use the lightest path your experiment can defend. The package never turns an unsuitable null into valid p-values.

01default

Explore

method="none"

Get descriptive effects and robust outlier scores when you are exploring or cannot defend a no-effect comparison.

No p-values, q-values, or significance mask
02matched prompts

Sign-flip test

method="signflip"

Use when per-prompt effects are independent or exchangeable and plausibly symmetric around zero under no effect.

Monte Carlo p-values under stated assumptions
03control runs

Empirical null

null_distribution=…

Pass task-specific control means that preserve the experiment while removing the relationship under test.

Inference relative to your control design
!

Important: labels and matching shapes record provenance; they do not prove that a control is scientifically valid.

03 / The audit loop

From prompt pair
to held-out evidence.

01

Define the effect

Choose a metric that returns one finite value per prompt. The built-in example uses correct-minus-incorrect logit difference.

02

Run the patching audit

Compare clean, corrupted, and patched runs across a declared component family such as attention heads or MLP outputs.

03

Correct the full search

Use Benjamini–Hochberg or Benjamini–Yekutieli after valid p-values exist. Pool related audits when they belong to one search.

04

Validate on held-out prompts

Select on one split, then measure joint effects on disjoint groups. This reduces prompt reuse, but cannot repair a misspecified null.

04 / A small API for a careful workflow

Start with PatchingAuditor.

The package keeps the main objects close to the analysis decisions you need to explain.

quick_start.py
from transformerlens_fdr import PatchingAuditor, logit_difference

# Choose the model, metric, and component family
auditor = PatchingAuditor(
    model=model,
    metric_fn=logit_difference,
    fdr_threshold=0.05,
    fdr_method="fdr_by",
    hook_type="attn_head",
)

results = auditor.run_patching_audit(
    clean_tokens, corrupted_tokens,
    correct_tokens, incorrect_tokens,
    method="signflip",
)
