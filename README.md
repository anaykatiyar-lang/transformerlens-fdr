# TransformerLens-FDR

[![Python 3.10+](https://img.shields.io/badge/python-3.10+-blue.svg)](https://www.python.org/downloads/)
[![TransformerLens v4.0.0+](https://img.shields.io/badge/transformer__lens-4.0.0+-orange.svg)](https://github.com/TransformerLensOrg/TransformerLens)

**Statistical analysis for activation patching in TransformerLens.** I built TransformerLens-FDR to make component-level patching effects, null assumptions, and multiple-testing corrections explicit and reproducible.

The package estimates how activation replacement changes a user-defined model score. It supports exploratory effect analysis and, when a defensible null model is supplied, significance testing with false-discovery-rate adjustment across the tested components. The statistical claim is only as reliable as the metric, prompt design, and null model used in the experiment.

---

## Research workflow

Every audit begins with a research question: **which model behavior should change when an activation is replaced?**

1. **Define the outcome.** For next-token preference, `logit_difference` subtracts the alternative token's logit from the target token's logit. For another behavior, provide a metric that returns one finite value per prompt.
2. **Specify the comparison.** Use matched clean and corrupted prompts, define target and alternative outcomes before inspecting component results, and apply the same metric throughout.
3. **Inspect effect estimates.** Run `python example_usage.py` for a compact GPT-2 example. The script uses one prompt and intentionally reports descriptive effects only; one prompt cannot estimate prompt-to-prompt variability.
4. **Choose an inferential method only when its null assumptions fit.** The guide below distinguishes sign-flip testing from a caller-supplied empirical null. If neither is defensible, keep the analysis exploratory.

---

## Why adjust for multiple testing?

When an analysis tests many heads, layers, or positions, some may appear unusual by chance. A fixed effect cutoff or a top-*k* list does not quantify that risk. False Discovery Rate (FDR) procedures adjust a family of valid p-values to control the expected proportion of false discoveries among the results declared significant, subject to each procedure's assumptions.

By default, the audit does not infer a null distribution from the components being tested. It reports patching effects and descriptive outlier scores; p-values and significance masks remain unset. This keeps exploratory rankings separate from statistical evidence.

### Choosing a metric and null model

Neither the outcome metric nor the null model is universal. Choose them from the scientific question and experimental design:

| Research question | Example metric | Candidate inference method |
| --- | --- | --- |
| Does patching change preference between two next tokens? | `logit_difference`: target-token logit minus alternative-token logit, per prompt | Sign-flip testing may be appropriate when prompt pairs are independent and the null distribution of paired effects is symmetric around zero. |
| Does patching change another task outcome? | A task-specific `metric_fn` returning one finite value per prompt | Supply a component-specific empirical null generated by controls that represent the no-effect condition. |
| Is the analysis exploratory, or is the null not yet justified? | A metric that represents the behavior of interest | Use the default `method="none"`; report effect estimates and descriptive rankings without significance claims. |

For all methods, specify the target and alternative outcomes before inspecting component results, and use the same metric on clean, corrupted, and patched runs. The package validates metric output shape and finiteness; it cannot determine whether a metric or control design answers the research question.

## Mathematical definitions

### 1. Normalized Patching Effect ($P$)
The normalized patching effect measures how much replacing an activation restores the clean score relative to the clean–corrupted gap:

$$ P = \frac{M_{\text{patched}} - M_{\text{corrupted}}}{M_{\text{clean}} - M_{\text{corrupted}}} $$

A value near `0` indicates little recovery; `1` indicates recovery of the clean–corrupted gap; values above `1` indicate overshoot. The ratio is undefined when clean and corrupted scores are equal.

### Significance testing and assumptions
A **null model** describes the results expected if the effect under study were absent. This package supports two routes:

- `method="signflip"` compares per-prompt effects under sign changes. Its validity requires independent prompt effects and a null distribution symmetric around zero; skewed null effects violate this assumption.
- An **empirical null** is a set of control effects designed to represent no effect. Pass values shaped `[n_controls, layers, components]`, with controls for each component. Validate the control design on data not used to construct the null where possible.

The package adjusts valid p-values across the tested family. Benjamini–Hochberg (BH) controls FDR under independence and certain positive-dependence conditions. Benjamini–Yekutieli (BY) controls FDR under arbitrary dependence and is typically more conservative. Neither procedure repairs invalid p-values or a misspecified null; if the no-effect comparison is not defensible, leave significance testing off.

At target level $\alpha$, FDR control bounds the **expected fraction of false discoveries among rejected hypotheses**, when p-values and procedure assumptions are valid:

$$ \mathrm{FDR} = \mathbb{E}\left[\frac{V}{\max(R, 1)}\right] \leq \alpha $$

Here, $R$ is the number of rejected hypotheses and $V$ is the number of those rejections that are false. This is an expectation over repeated applications of the procedure, not a guarantee about the false-discovery fraction in one particular analysis.

### Circuit Localization Index (CLI)
The CLI summarizes whether absolute patching effects are concentrated in a few components or distributed across many. It is descriptive, not a significance test. Values near $1$ indicate concentration; values near $0$ indicate diffuse effects.

Here, $w_i$ is component $i$'s share of the total absolute patching effect; it is not a statistical p-value.

$$ w_i = \frac{|P_i|}{\sum_j |P_j| + \epsilon} $$
$$ H = - \sum_i w_i \log_2 (w_i + \epsilon) $$
$$ \text{CLI} = 1 - \frac{H}{\log_2(N)} $$

## API overview

The main entry point is `PatchingAuditor`.

### `PatchingAuditor` (Class)
Runs component-level activation-patching audits.
- **`__init__(model, metric_fn, fdr_threshold=0.05, fdr_method='fdr_bh', n_perm=9999, hook_type='attn_head')`**
  `metric_fn` must return one value per prompt (`[B]`). BH requires valid p-values and independence or an appropriate positive-dependence condition; BY allows arbitrary dependence but still requires valid p-values.
- **`run_patching_audit(...)`**  
  Patches all components. Set `method="signflip"` to use sign-flip testing, or pass a per-component `null_distribution`. With neither, the audit returns effect estimates without inferential fields.
- **`run_joint_patching(..., patching_mask)`**  
  Patches selected components simultaneously and reports their joint normalized effect.

### `AuditResults` (Dataclass)
Returned by the auditor. Contains:
- `raw_patching_effects`: Mean point estimate per component `[layers, components]`.
- `per_prompt_effects`: Per-prompt effects `[layers, components, prompts]`.
- `adjusted_effects`: Point estimates centered by the same null used for inference; robust-centered when exploratory.
- `p_values` / `q_values`: Optional statistical results. A q-value is a p-value adjusted for testing multiple components; these fields are `None` unless a null method is selected.
- `significant_mask`: Which components passed the selected significance cutoff; shown only when p-values were produced.
- `outlier_scores`: Descriptive scores for ranking unusual measurements; they are not p-values.
- `calibrated` / `null_description`: Whether a significance method ran and which null model was used.
- `cli_score`: The Circuit Localization Index float.
- `summary_df`: A neat Pandas DataFrame of all results.

### Metrics & Stats (Functions)
- **`logit_difference(logits, correct_tokens, incorrect_tokens)`**  
  Returns the correct-minus-incorrect logit difference for each prompt.
- **`normalized_patching_effect(patched, clean, corrupted)`**  
  Calculates $P$.
- **`circuit_localization_index(normalized_effects)`**  
  Calculates the CLI.
- **`apply_fdr_adjustment(p_values, alpha, method)`**  
  Runs the statsmodels FDR logic.
- **`signflip_p_values(effects, n_perm, two_sided)`**
  Computes Monte Carlo sign-flip p-values for `[layers, components, prompts]` under a symmetry-about-zero null.

### Visualization (Functions)
- **`plot_fdr_heatmap(results, title)`**  
  Renders a heatmap only when calibrated significance results are available. The plot does not establish causal validity by itself.

## Published benchmark

I check the Benjamini–Hochberg adjustment against the published 15-hypothesis example in Benjamini and Hochberg (1995). At target FDR 0.05, the implementation rejects the same four hypotheses as the paper's BH procedure.

The regression test uses the paper's ordered p-values and checks the rejected hypotheses directly:

```bash
python -m pytest -q tests/test_published_benchmark.py
```

Reference: Benjamini, Y. and Hochberg, Y. (1995), “Controlling the False Discovery Rate: A Practical and Powerful Approach to Multiple Testing,” *Journal of the Royal Statistical Society: Series B*, 57(1), 289–300. [DOI: 10.1111/j.2517-6161.1995.tb02031.x](https://doi.org/10.1111/j.2517-6161.1995.tb02031.x). The paper's p-values and result are also available in its [full text](https://www.stat.cmu.edu/~ryantibs/journalclub/benjamini_1995.pdf).

## Installation and quick start

### Option 1: Install Directly from GitHub
Anyone can install this directly into their environment without needing to clone the repo:
```bash
pip install git+https://github.com/anaykatiyar-lang/transformerlens-fdr.git
```

### Option 2: Clone for Local Development
If you want to edit the code or run the tutorials:
```bash
git clone https://github.com/anaykatiyar-lang/transformerlens-fdr.git
cd transformerlens-fdr

# Install editable with tests
pip install -e .[test]

# Run the provided example scripts!
python example_usage.py
python advanced_tutorial.py

# Reproduce the published BH reference benchmark
python -m pytest -q tests/test_published_benchmark.py
```

## Limitations

The published benchmark verifies the multiple-testing adjustment on one reference example; it does not validate every method of producing p-values or every model-and-dataset combination. Calibration depends on the chosen metric, prompt sampling, null model, and dependence assumptions. The CLI and outlier scores summarize observed effects; by themselves, they do not establish a component's reliable or general causal role.
